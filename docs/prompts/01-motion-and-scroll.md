# 01. Движение при «уменьшении движения», пошаговая прокрутка, плашки в строке

Перед отправкой: включите режим плана (Shift+Tab).

## Промпт
```
Прочитай CLAUDE.md, docs/SPEC.md (разделы «Прокрутка», «Уменьшение движения», экран 1) и docs/ISSUES.md.
Исправь три проблемы из docs/ISSUES.md. Сторонние библиотеки не добавляй.

1. Сайт замирает при prefers-reduced-motion: reduce (у меня в Windows выключены эффекты анимации).
   Реализуй политику из таблицы «Уменьшение движения» в SPEC.md:
   - в js/main.js раздели флаг reduced на два режима: крупное движение (параллакс, вращения, полёты пакетов,
     конфетти, магнит, перелёт карточек) отключаем; смену состояний оставляем, но заменяем движение
     на проявление opacity за 300–400 мс на месте;
   - в css/style.css блок @media (prefers-reduced-motion: reduce) сейчас глушит ВСЕ анимации.
     Перепиши: глуши только перемещения/вращения/масштаб, а проявления (opacity) оставь;
   - проверь каждый модуль: heroWord, heroBoard, orbit, autopost, sandbox, how, price, chart, cube, start.
     Для каждого напиши в ответе одной строкой, что он делает в режиме reduce.

2. Пошаговая прокрутка по экранам (SPEC.md, «Прокрутка»):
   одно движение колеса / свайп / PageDown / PageUp / стрелки = плавный переход на соседний экран за 600–800 мс.
   Экран выше окна сначала прокручивается внутри себя, на краю — переход дальше.
   Учитывай липкую шапку. Тачпад с инерцией не должен проскакивать по несколько экранов.
   Не перехватывай события, когда пользователь тянет плашку в песочнице, поворачивает куб или орбиту,
   двигает ползунок или фокус в поле ввода. При высоте окна < 600 px — обычная прокрутка.
   Точки #dots и полоса прогресса должны продолжать работать.

3. В бегущей строке под доской (#netstrip) перед каждым названием добавь цветную плашку соцсети
   из массива NETS (класс .chip, размер как .chip--xs, но 24 px). Бесконечная прокрутка без рывка на стыке.

Проверь сам (можно через Playwright, если он есть, иначе по коду):
- с reducedMotion: 'reduce' слово в плашке меняется, карточки на доске меняют колонки;
- без него всё работает как раньше;
- ширина 390 px — нет горизонтальной прокрутки, нет ошибок в консоли.
Обнови docs/ISSUES.md (отметь исправленное) и при необходимости docs/SPEC.md. Сделай коммит.
В конце напиши, как мне проверить каждый пункт руками.
```

## Как проверить руками
1. В Windows включите обратно «Эффекты анимации» — всё должно двигаться полностью.
2. Выключите их — слово в плашке всё равно меняется (проявлением), карточки на доске меняют колонки, но ничего не летает и не крутится.
3. Одна прокрутка колесом — переход ровно на следующий экран. На песочнице плашки перетаскиваются, страница при этом не уезжает.
4. В DevTools (F12) → значок телефона → 390 px: свайп листает экраны, первый экран с доской сначала докручивается до конца.
